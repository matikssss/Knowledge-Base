| Команда                       | Описание                                                 |
| ----------------------------- | -------------------------------------------------------- |
| `git init`                    | Создать новый репозиторий в текущем каталоге             |
| `git status`                  | Показать текущее состояние (что изменено, что в индексе) |
| `git add <файл>`              | Добавить файл в индекс                                   |
| `git add .`                   | Добавить все изменения в индексе                         |
| `git commit -m "..."`         | Зафиксировать изменения из индекса                       |
| `git log`                     | Показать историю коммитов                                |
| `git log --oneline`           | Компактная история (одна строка на коммит)               |
| `git diff`                    | Показать незафиксированные изменения                     |
| `git diff --staged`           | Показать изменения, добавленные в индекс                 |
| `git show <хеш>`              | Показать содержимое конкретного коммита                  |
| `git restore <файл>`          | Откатить один файл к версии из последнего коммита        |
| `git restore .`               | Откатить все файлы в рабочем каталоге                    |
| `git restore --staged <файл>` | Удаление изменений из индекса                            |
`git diff` Index ↔ Working tree

`git diff --staged` HEAD ↔ Index

`git diff HEAD` HEAD ↔ Working tree

В `git show --no-patch HEAD` команда `show` показывает текущий коммит, а флаг `--no-patch` **скрывает патч**, то есть список изменений файлов. Остаются сведения о коммите. Для созданного здесь обычного merge commit строка `Merge:` показывает короткие хеши двух родителей: сначала прежнюю вершину `main`, затем вершину `feature`. Сверьте их с графом истории.

Команда `git check-ignore -v` поможет определить, какое именно правило заставляет Git игнорировать файл.
## Безопасные способы исправления
`git restore` по умолчанию восстанавливает рабочую версию именно из Index.
- Отменить незакоммиченные изменения в одном файле: `git restore путь/к/файлу`. 
- Убрать файл из индекса, но оставить его в папке: `git restore --staged путь/к/файлу`.
- Создать новый коммит, отменяющий уже опубликованное изменение: `git revert <коммит>`.

Не применяйте `git reset --hard` и принудительную отправку в общую ветку, пока не понимаете последствия. Эти команды полезны, но способны уничтожить незакоммиченные данные или переписать историю коллег.

git restore --staged <файл> -  Git берёт версию из `HEAD` и восстанавливает её в индексе, но файл в рабочей директории остаётся без изменений.
git restore <файл> - Git берёт версию из индекса и восстанавливает её в рабочей директории. ==🔴Данные в рабочей директории теряются==

## Справочник команд ветвления
| Команда                     | Описание                              |
| --------------------------- | ------------------------------------- |
| `git branch`                | Показать список веток                 |
| `git branch <имя>`          | Создать новую ветку                   |
| `git switch <имя>`          | Переключиться на ветку                |
| `git switch -c <имя>`       | Создать ветку и сразу переключиться   |
| `git merge <имя>`           | Слить указанную ветку в текущую       |
| `git log --oneline --graph` | История с визуализацией веток         |
| git branch -f main C1       | переместить указатель ветки           |
| `git branch -d <имя>`       | Удалить ветку (только если она слита) |
«**Совет.** Если во время слияния вы запутались и хотите отменить всё, выполните `git merge --abort` — Git вернёт файлы в состояние до начала слияния.» `git merge --abort` — это отмена попытки слияния, а не отмена уже выполненного коммита или развёрнутого релиза.
**Fast-forward** возможен, когда текущий коммит является предком коммита, который мы хотим влить.
==🟢`git switch --detach C1` - HEAD начинает указывать непосредственно на C1==

| Режим     | Куда переместится main | Индекс            | Рабочие файлы      |
| --------- | ---------------------- | ----------------- | ------------------ |
| `--soft`  | `C1`                   | Останется прежним | Останутся прежними |
| `--mixed` | `C1`                   | Состояние `C1`    | Останутся прежними |
| `--hard`  | `C1`                   | Состояние `C1`    | Состояние `C1`     |
Правило для запоминания: `soft` трогает только указатель, `mixed` — указатель и индекс, `hard` — указатель, индекс и рабочие файлы.
## Как команды перемещают изменения

- `git add` переносит выбранные изменения из рабочего каталога в индекс.
- `git commit` сохраняет подготовленные изменения в локальной истории.
- `git push` отправляет локальные коммиты в удалённый репозиторий.
- `git fetch` получает изменения с сервера и обновляет ссылки вида `origin/main`, но не меняет рабочие файлы.
- `git pull` получает изменения и сразу применяет их к текущей ветке. Обычно это `fetch`, после которого выполняется `merge` или `rebase` — в зависимости от настроек.
- `git switch` переключает ветки. Универсальная команда `git checkout` тоже умеет это делать, но в новых версиях Git для переключения веток понятнее использовать `git switch`.
- `git merge` и `git rebase` объединяют историю разных веток разными способами.
